# Internationalization (English · French)

OpportunityOS is bilingual. Every screen, every label and every sentence the
deterministic engines generate exists in English and in French. This page is
the contract every contributor follows.

## Locale resolution

- The locale is **not** in the URL. Every route is identical in both languages.
- Order: the `locale` cookie (explicit choice) → the browser's `Accept-Language`
  header → English.
- The choice is stored on the account (`User.locale`) and copied into the cookie
  at login, so it follows the user to the next browser.
- `src/i18n/server.ts` — `getLocale()` (cached per request) and `getT()` for
  server components, route handlers and actions.
- `src/i18n/client.tsx` — `useLocale()` and `useT()` for client components.
  `LocaleProvider` sits in the root layout; both dictionaries are bundled.
- `LanguageSwitcher` (`src/components/layout/language-switcher.tsx`) calls
  `setLocaleAction` and refreshes.

## Dictionaries

- `src/i18n/dictionaries/en/<section>.ts` is the reference. French lives in
  `src/i18n/dictionaries/fr/<section>.ts` and is typed
  `Section<typeof en>`: a missing or extra French key is a compile error.
- Sections: `common`, `labels`, `marketing`, `auth`, `layout`, `dashboard`,
  `settings`, `chat`, `discovery`, `shared`, `evidence`, `assumptions`,
  `opportunity`, `value`, `experiments`, `report`, `validation`, `frontier`,
  `validity`, `nextAction`, `scoring`, `mock`. Add keys to an existing section;
  a new section must be registered in both `index.ts` files.
- Keys are dot paths: `t("dashboard.title")`, `t("labels.verdict.KILL")`.
  Name keys by meaning (`emptyState.title`), never by the English wording.
- `labels.*` exposes every enum/vocabulary table (`VERDICT_LABELS`,
  `DESIGN_LEVEL_LABELS`…) under a stable key. The English tables stay where the
  engines define them (they are canonical); the French tables are hand-written
  in `fr/labels.ts`. Render an enum with `t(\`labels.verdict.${verdict}\`)`.

## The `t` function

```ts
t("evidence.add"); // key
t("value.linked", { count: 3 }); // interpolation + plural
t(frontier.blocker.message); // SystemMessage or string
```

Templates use a small ICU subset:

```
{name}                                   interpolation
{count, plural, =0 {none} one {# item} other {# items}}
{status, select, OBSERVED {observed} other {not observed}}
```

`#` is the number; plural categories follow `Intl.PluralRules` (French: 0 and 1
are `one`). A plain string that is not a key is returned unchanged, so user
content and legacy rows can go through `t()` safely.

## System messages (engines)

Sentences produced by the engines (`src/services/**`) are persisted with the
opportunity: frontier blockers, inferences, next best actions, validity
checks, knowledge changes, interpretations… They must render in the current
language later, so an engine never returns a bare English string for such a
sentence. It returns a **`SystemMessage`**:

```ts
import { msg } from "@/i18n/messages";
msg("frontier.blocker.lowFit", { level: msg(`labels.proofRung.${level}`), fit: 39, required: 40 });
// → { key, params, text: "Mechanism: only low-fit evidence is linked (best fit 39/100, required 40) — …" }
```

- `text` is the canonical English rendering: tests assert on it
  (`expect(blocker.message.text).toMatch(/…/)`) and legacy consumers show it.
  Keep the English templates identical to the sentences the engines produced
  before (the tests are the specification).
- Parameters may be strings, numbers or nested `SystemMessage`s (labels,
  claim statements, sub-sentences). User content (names, statements) is passed
  as a string parameter and never translated.
- Field type: `SystemMessage` on engine outputs; `LocalizedText`
  (`string | SystemMessage`) wherever persisted JSON is read back, since rows
  written before this change hold plain strings.
- Database text columns keep the English text and gain a `…Message Json?`
  sibling holding the descriptor (`inference` / `inferenceMessage`,
  `interpretation` / `interpretationMessage`).
- Composite descriptions of structured data (a scope, a validity summary) are
  rendered at display time from the object: `describeScope(scope, locale)`.
- `textOf(value)` gives the English text of a localized value (logs, tests);
  markdown copied to the clipboard is rendered with the user's `t`.

## Rules

1. Never translate enum _values_, dictionary keys, JSON keys or the status
   vocabulary the AI is told to use (UNKNOWN, HYPOTHESIS, EVIDENCE, FACT).
2. Never translate user content or demo content stored in the database.
3. Never build a sentence by concatenating translated fragments; use one
   template with parameters so word order can differ per language.
4. Dates and numbers go through `src/i18n/format.ts`.
5. The AI analyst answers in the conversation locale (`languageInstruction`);
   the mock provider has French templates.
6. French typography: a no-break space (U+00A0) before `?`, `!`, `:`, `;` and
   inside « guillemets »; accents on capitals (É, À); the four scores are
   proper nouns (Potentiel de l’opportunité, Confiance dans les preuves, Force
   de valeur, Confiance causale) and the Proof Frontier is « Frontière de preuve ».
